# 주저리 → PRD → 보고자료 (HTML + Figma)

저장소 루트(이 스킬이 들어 있는 폴더의 `../../..`)에서 실행한다. 규칙은 루트 `CLAUDE.md` 를 먼저 읽고 따른다.

## 0. 입력 받기
- 원문: 사용자가 붙여넣은 텍스트 또는 파일 경로. 없으면 요청한다.
- 분량: 기본은 **가볍게 5~7장**. 원문이 "지금까지 작성한 내용" 같은 기존 자료를 근거로 지정하면 그 자료를 읽되 요약만 옮긴다.
- 슬러그: 원문 내용으로 영문 소문자·하이픈 2~4단어를 만든다(예: `inventory-upgrade`). 폴더는 `reports/<오늘 YYYY-MM-DD>-<슬러그>/`. 이미 있으면 `-2` 를 붙인다.
- 청중·보고 성격이 원문에 없으면 묻지 말고 PRD에 `[확인 필요]` 로 두고 진행한다.

## 1. 원문 저장 — `00_원문.md`
머리말만 붙이고 본문은 **한 글자도 고치지 않는다**(맞춤법·줄바꿈 포함).

```markdown
---
received: YYYY-MM-DD
source: 채팅 붙여넣기 | <파일명>
---

<원문 그대로>
```

## 2. 공개 적합성 점검 (멈춤 지점)
공개 저장소에 올라가므로 원문에서 아래를 찾는다.
- 실명·전화·이메일·주소·주민/사업자번호 등 개인정보
- 고객사·거래처 이름, 계정·비밀번호·키·토큰·내부 URL
- 비공개로 보이는 매출·단가·계약 조건

**하나라도 있으면** 목록을 보여주고 "가명 처리 / 삭제 / 그대로" 중 하나를 고르게 한 뒤 진행한다. 가명 처리하면 `00_원문.md` 본문도 그 부분만 바꾸고 머리말에 `redacted: <바꾼 항목 요약>` 을 적는다. **없으면 멈추지 않고 진행한다.**

## 3. PRD 작성 — `01_PRD.md`
`templates/PRD_템플릿.md` 를 복사해 채운다.
- 머리말(title·slug·date·author·audience·purpose·summary)은 `scripts/build-index.mjs` 가 목록에 쓴다. 빠뜨리지 않는다.
- **원문에 없는 사실은 지어내지 않는다.** 흐름상 채운 것은 7절 "추정·보완한 내용"에, 모르는 것은 8절 "확인 필요"와 해당 문장 끝 `[확인 필요]` 로 남긴다.
- 숫자는 6절 표에 구분(근거 있음 / 자리표시자 / 내부 결정)과 함께 모은다. 근거 없는 값은 `N주 (예: 2주)` 꼴로 쓴다.
- 슬라이드 명세(5절)는 **정의된 7개 유형만** 쓴다. 보통 5~9장. 첫 장 `cover`, 둘째 장 `summary`, 끝 장 `next` 를 기본으로 하고 사이를 원문 내용에 맞는 유형으로 채운다.
- 리드는 제목의 반복이 아니라 그 장의 **결론 문장**이다.
- 한 장에 너무 많으면 나눈다: bullets 6개, table 6행×5열, flow 6단계, summary 4포인트가 상한.

## 4. 웹 보고자료 — `index.html`
`templates/report.html` 을 복사하고 `<main>` 안의 예시 슬라이드를 지운 뒤 PRD 5절 순서대로 같은 마크업으로 채운다.
- 유형 ↔ 마크업: cover `slide--cover` / summary `.points > .point` / bullets `ul.bullets` / table `.table-wrap > table` (+강조 행 `tr.hl`, 주석 `.note`) / flow `.flow > .step` (+강조 `.on`) / compare `.compare > .col` (+오른쪽 `.after`) / next `table`.
- `[확인 필요]` 는 `<span class="check">확인 필요</span>` 로 바꾼다.
- `<title>` 과 cover 제목은 PRD title과 같게. 슬라이드 번호 `.no` 는 두 자리.
- PRD에 없는 내용을 HTML에서 추가하지 않는다.

## 5. Figma 초안
1. 루트 `CLAUDE.md` 의 `FIGMA_FILE_KEY` 를 확인한다. **미정이면** 사용자에게 편집 가능한 팀 파일 URL을 받아 기록한다. 받을 수 없으면 이 단계를 건너뛰고 마지막 보고에 "Figma 건너뜀"을 적는다. `create_new_file`(Drafts)은 쓰지 않는다 — MCP 계정이 사용자 본인 계정이 아니라 사용자가 편집할 수 없다.
2. `use_figma` 를 쓰기 전에 **figma-use 스킬을 반드시 먼저 로드**한다(Figma 플러그인의 `/figma-use`, 없으면 `skill://figma/figma-use/SKILL.md`).
3. `CLAUDE.md` 에 적힌 페이지(`AX교육 과제제출`)에 그린다. 없으면 만든다. 보고서마다 새 줄(y = 기존 프레임 최하단 + 400)에 놓고, 줄 왼쪽 위에 `YYYY-MM-DD <title>` 라벨을 둔다. **기존 프레임은 건드리지 않는다.**
4. PRD 슬라이드마다 프레임 1장. 아래 규격을 따른다(HTML과 같은 토큰).

| 항목 | 값 |
|---|---|
| 프레임 | 1920×1080, 흰 배경, 이름 `S01 cover` 처럼 `S번호 유형`, x = (번호−1) × 2080, y = 그 보고서 줄의 y |
| 여백 | 좌우 120, 위 96 |
| 폰트 | Noto Sans KR (Pretendard는 MCP에서 로드 안 됨 → 데스크톱에서 일괄 교체) |
| 슬라이드 번호 | 16 Regular #555B66 |
| 제목 | 36 Bold #003879 |
| 리드 (레이어명 `리드`) | 19 Medium #111111 단일 스타일 — 부분 강조 없음 |
| 본문 | 16 Regular #111111, 표 15 |
| 테두리 | 1px #D9DDE3, 표 헤더 #F1F3F6, 강조 #E8F1FB, 신규·확인 필요 #E8710A |
| cover | 배경 #003879, 제목 64 Bold 흰색, 부제 28 흰색 85%, 날짜·작성자 20 흰색 75% 하단 |
| summary | 포인트 카드 가로 배치, 위 테두리 4px #003879 |
| flow | 단계 박스 가로 배치 + 사이 화살표, 강조 단계는 #E8F1FB 배경 + #003879 테두리 |
| compare | 2단, 오른쪽 열 #E8F1FB 배경 + #003879 테두리 |
| `[확인 필요]` | 해당 텍스트 뒤에 주황 꼬리표(#E8710A 배경, 흰 글씨 13 Bold) |

- 표는 auto layout 프레임으로 만들고(행 = 가로 auto layout, 셀 = FILL), 높이는 내용에 맞춘다.
- 선(화살표 등)을 벡터로 그릴 때는 경로를 bbox 최소값 기준 상대 좌표로 만들고 x, y를 그 최소값에 둔다.
- 다 그리면 `get_screenshot` 으로 2~3장을 확인하고, 글자 넘침·겹침이 있으면 고친다.
5. 만든 파일 키·페이지 이름을 PRD 머리말 `figma:` 에 적는다.

## 6. 목록 갱신·확인
```
node scripts/build-index.mjs
```
- `index.html`(루트)에 새 보고서가 보이는지 확인한다.
- 가능하면 로컬에서 열어 본다(예: `npx serve .` 또는 브라우저로 파일 열기).

## 7. 커밋·push
1. `git status` 로 이번 보고서 폴더와 `index.html` 만 바뀌었는지 확인한다. 다른 변경이 섞여 있으면 따로 알린다.
2. 커밋: `report: <title>`
3. **push 전에 사용자 확인을 받는다**(공개 저장소). 확인되면 `git push`. Vercel이 자동 배포한다.

## 8. 마무리 보고
짧게:
- 만든 파일 3개 경로
- 배포 URL `https://<vercel 도메인>/reports/<폴더>/` (push 했을 때)
- Figma 페이지 링크 (만들었을 때)
- PRD 8절 "확인 필요" 항목 수와 가장 중요한 것 1~3개
